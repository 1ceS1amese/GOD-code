# Phase 99: TUI per-session event buffers

Phase99 adds per-live-session event buffers to `god-code tui`. Events generated by one live session are stored under that session id, and the events pane swaps to the active session's buffer when live sessions are switched.

This phase is a focused TS Host TUI correctness improvement. It builds on Phase97/98 live session switching and does not add JSON-RPC methods, change Python Engine protocol shape, or change transcript schema, provider APIs, MCP protocol, plugin manifests, permission policy, or host tool execution boundaries.

## Implementation status

Implemented in this phase:

- Added `eventsBySessionId` to `TuiState`.
- `session_started` now initializes / restores the active session event buffer.
- `append_event`, `append_assistant_delta`, and `finalize_assistant_message` can target a specific session id.
- GOD-code runtime events are routed by `event.session_id`.
- Live session switching restores the target session's events pane contents.
- Background session events update their own buffer without replacing the active events pane.
- Focused tests in `ts-host/test/tui.test.ts`.

## Goals

- Prevent events from different live sessions from mixing in the same visible events pane.
- Keep background live session events available for later session switches.
- Preserve assistant delta coalescing per session.
- Keep event routing local to TS Host TUI state and controller event conversion.

## Non-goals

- No persistent event store beyond in-memory TUI state.
- No transcript schema migration.
- No cross-process event replay.
- No per-session approval policy change.
- No JSON-RPC, protocol, provider, MCP, plugin, or tool boundary changes.

## Buffer behavior

Current behavior:

- Initial TUI startup events are copied into the first live session buffer.
- A newly created live session starts with an empty visible event buffer, then receives its own creation/system events.
- Runtime events with `session_id` update that session's buffer.
- If the event target is not the active live session, the active events pane is not replaced.
- Switching or activating a live session restores that session's buffered events and resets event scroll offset.

## Acceptance criteria

- Events are stored per live session id.
- Switching live sessions changes the visible events pane to that session's buffer.
- Background session events do not overwrite the active session's events pane.
- Assistant streaming coalescing remains per session.
- Focused TUI / REPL tests and TS typecheck pass.
- No protocol/schema/provider/MCP/plugin boundary changes are required.
